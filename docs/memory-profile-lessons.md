# 记忆档案的写法：一份外部样本带来的六条启发

> 来源：2026-11-12 由 ChatGPT 依据「聊天上下文 + 历史对话 + 长期记忆」合成的一份个人档案（约 23 KB / 11 节）。
> 原文含个人信息，只保存在 `data/private/reference/`，不进仓库。本文只记录可复用的写法。

## 样本长什么样

11 节：摘要 / 背景 / 设计理念 / 项目卡（9 个）/ 求职主线 / 比赛 / AI 使用观 / 个人表达 / 沟通偏好 / 时间线 / **不要擅自补全** / **短版背景**。

它不是原始记录的复刻，而是**合成物**。价值不在「全」，在**知道自己不知道什么**。

## 六条可复用的写法

### 1. 认知标签：区分「自述 / 观察 / 待核实」

样本开头就声明：

> 「自述」指本人曾明确表达；「观察」指基于多次对话的归纳，不等同于事实；「待核实」表示没有足够信息确认最新状态。尤其不应把历史助手的评价直接当作本人观点。

**出处回答「哪来的」，认知状态回答「这算事实还是推断」。** 两者缺一不可。

对应到我们的模型：L3.1 的 `status`、L5 的 `support` 已经能推出这个标签，只是没有显式写出来。

### 2. 「不要擅自补全」清单

样本第 10 节列了 6 条**禁止推断**的事，例如：

- 招聘状态：不能把漫长等待认定为筛选失败；
- 反馈细节：不能凭缺少原文推测落选原因；
- 项目最新状态：阶段性进度 ≠ 当天状态；
- 架构命名：历史上改过层级名，不能把旧方案当定稿；
- 个人特点：跨对话归纳不能当不可证伪的性格标签；
- 记忆完整性：不能宣称覆盖所有聊天。

**「未决清单」是待解决的问题，「不要擅自补全」是禁止下的结论。** 方向相反，后者更能防止模型胡说。

### 3. 项目卡的「边界」字段

每个项目都写「它不是什么」：

> 这是个人兴趣与求职辅助项目，不以商业化、长线运营或规模传播为目标，不宜套用商业游戏的运营指标。

这防止模型用错尺子。我们的社区报告只有「发生了什么」，没有「别用什么标准衡量它」。

### 4. 短版背景

一段可直接复制的 300 字，给其他 AI 用。这正是「模型交接层」的成品形态。

### 5. 维护规则

样本文末：

> 后续如修订，请保留原有事实的时间戳，对状态变更追加「更新记录」，避免用新印象覆盖旧事件。

这就是我们的双时态模型，用一句话说清楚了。档案本身应该把这条规则写在开头。

### 6. 诚实的范围声明

> 这不是原始聊天记录的完整复刻，也不代表系统中所有可检索的记忆。

## 对照

| 维度 | 样本 | 我们（改前） |
|---|---|---|
| 篇幅 | 23 KB / 11 节 | 3 KB / 7 节 |
| 认知标签 | 自述 / 观察 / 待核实 | 只有出处 |
| 禁止推断 | 有（6 条） | 无 |
| 项目边界 | 有 | 无 |
| 短版 | 有 | 无 |
| 维护规则 | 有 | 无（但双时态已实现） |

## 落到代码上的五个改动

1. **profile 条目加 `epistemic`**：`stated` / `observed` / `unverified`，由 L3.1 的 `status` 与 L5 的 `support` 推导；
2. **profile 加「不要擅自补全」一节**：从 L5 的 `open` 与社区报告的未决里挑出**禁止推断**的条目；
3. **社区报告加「边界」字段**：这条线**不是**什么、别用什么标准衡量；
4. **生成 `memory-brief.md`**：300 字短版，给模型直接复制；
5. **profile 开头加范围声明 + 维护规则**。

## 一个判断

样本第 10 节那 6 条，比前面 9 节更能防止模型胡说。我们的 L5 有 `support` 计数，但缺这种**显式的否定知识**——这是下一步最值得补的一块。
