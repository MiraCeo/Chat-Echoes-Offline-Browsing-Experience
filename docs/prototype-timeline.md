# 聊天时间轴原型（P1–P5）

只读设计原型，用来比较“会话节点 / 日期节点”两种定位，以及“基础 / 进度条”两种编码。
它不进入正式页面、不参与生产构建，也不改写 `archive/`；正式 `timeline.html` 与列表视图不受影响。

## 生成与查看

```powershell
npm run prototype:timeline
```

输出 `data/private/timeline-prototypes/index.html`，直接双击打开；顶部标签或 `?v=p1`…`?v=p5`
切换变体。数据来自 `replay/public/timeline-index.json` 与 `replay/chats.json`（当前 36 个会话，
2026-07～2026-10，构建机本地时区）；新增会话后先跑 `npm run library`，再跑原型生成。

## 五个变体

| 变体 | 定位 | 编码 | 不编码 |
|---|---|---|---|
| **P1 会话基础** | 横轴上每个节点=一条会话，卡片上下交替 | 先后顺序 | 真实间隔、跨度、重叠 |
| **P2 会话进度** | 同 P1，卡片内加逐日进度条 | 整条=该会话自身跨度，每格一天，填充=有消息（如 2/3） | 跨会话绝对时长（所有条等宽） |
| **P3 日期基础** | 横轴上每个节点=一个有会话的日期，日期等距 | 日期定位；日期节点分支挂当天会话（按开始时间，标注持续天数） | 真实日历比例、空日期占位；不做缩放 |
| **P4 日期进度** | 同 P3，卡片内加逐日进度条 | 日期定位 + P2 的逐日填充 | 跨会话绝对时长；空日期 |
| **P5 跨节点基础** | 月份分区、按天压缩的日期轴；3 条泳道 | 每条会话一条纯色横条，从开始日跨到结束日；同泳道不重叠 | 条内缺口；缩放；跨会话标签 |

P1/P2 是**会话定位**：一条会话一个节点。P3/P4 是**日期定位**：只有有会话的日期才有一个节点，
日期之间等距；P4 的日期卡片用逐日格子表达“当天这条会话持续了几天、哪几天有消息”。

P5 是**跨节点定位**：日期轴按天压缩（28px/天、月份分区），会话不再是一张卡，而是一条纯色横条，
从开始日跨到结束日；3 条泳道按区间分配，当前 36 条会话的最大并发正好是 3，所以可以保证同泳道
不重叠、3 条泳道互不交叉。条上空间不足时显示编号，编号与下方图例对应。

当前数据：36 条会话、26 个有会话的日期、单日最多 3 条；所有会话的进度条一共 99 个格子，
其中 77 个填充。

## 已观察到的取舍

- **P1** 最干净、最像“时间线”，但横轴只是等距槽位，不回答“隔了多久、覆盖多长”。
- **P2** 在不增加新轴的情况下补上了“跨度 + 缺口”：23 天跨度、5 天有消息的会话会是一条长条里
  5 个深格和 18 个浅格；代价是所有条等宽，表达比例而不是绝对时长，长跨度的格子会很细。
- **P3** 日期节点让“同一天有几条会话”非常直观，也自然跳过没有会话的日期；代价是没有空日期占位，
  看不出“中间停了多久”。日期节点按首条消息日期归属，跨天会话只在开始日出现一次。
- **P4** 把 P2 的进度条放进日期卡片，既能按日期找，又能看单条会话的持续与缺口；但卡片更拥挤，
  9px 的元信息偏小。
- **P5** 直接把“延续”画成横条长度：36 条会话、3 条泳道、0 交叉；纯色基础样式下，短会话只能显示
  编号，靠下方图例识别；28px/天时一屏约一个月，适合“月级详细图”，再往外看需要缩放。
- 共同问题：P1–P4 一屏只放 4 张会话卡（36 条需要横向拖动约 8,300px）；月份标签只在每月第一张卡
  上方，滚到月中就看不到；缺少图例；P2/P4 的“格子缝隙”和“空格”需要更清楚地区分。

## 还需要定的事

1. 正式时间线用**会话定位**（P2）、**日期定位**（P4）还是**跨节点**（P5），或三者切换；
2. 日期节点按“首条消息日期”还是“当天有消息”（跨天会话会出现在多个日期）；
3. 日期之间：等距跳过空日期，还是按日历留白；
4. 时间轴方向：最新在右（当前）还是最新在左；初始是否停在最新；
5. 空日期、月份刻度、图例、缩放、窄屏退化（是否改单列）怎么做；
6. 是否作为 `列表 | 时间轴` 的第二视图，保留现有列表为默认。

看过 P1–P5 之后再定；在这之前不改正式页面的数据与交互。
