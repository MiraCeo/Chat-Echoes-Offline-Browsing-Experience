# 聊天时间轴原型（P1–P4）

这是**只读设计原型**，用来比较“竖线 + 左右交替 + 覆盖时间”的几种画法；它不进入正式页面、
不参与生产构建，也不改写 `archive/`。正式 `timeline.html` 与当前列表视图都不受影响。

## 生成与查看

```powershell
npm run prototype:timeline
```

输出 `data/private/timeline-prototypes/index.html`，直接双击打开；顶部标签或 `?v=p1`…`?v=p4`
切换变体。同目录还会生成本地截图（`p1-1280.png`、`p1-480.png`、`*-1280-full.png`、`contact.png`），
仅作对比用，不入库。

数据来自 `replay/public/timeline-index.json` 与 `replay/chats.json`：当前 36 个会话，
2026-07～2026-10，时间均为构建机本地时区。卡片链接指向 `replay/conversations/<id>.html` 的真实本地页。
新增会话后先跑 `npm run library`，再跑原型生成。

## 四个变体

| 变体 | 布局 | 编码什么 | 不编码什么 |
|---|---|---|---|
| **P1 等距** | 竖线 + 左右交替卡片 | 先后顺序 | 真实间隔、跨度、重叠 |
| **P2 横向月轴** | 横向可拖动画布（每月固定 30 天） | 位置=首条时间、条长=首末跨度；可平移查看 4 个月 | 真实日历比例（31 日按月末处理）；不做缩放 |
| **P3 覆盖条** | P1 的竖线卡片 + 卡片内连续条 | 跨度（按最长会话归一化） | 全档案真实位置；条都从左侧开始 |
| **P4 活跃日** | P1 的竖线卡片 + 卡片内点串 | 真的有消息的日子、停顿与回访 | 连续覆盖；点之间的空白没有比例尺 |

P2 用横向可拖动画布，每月固定 30 天；它不是真实日历比例（31 日按月末处理），但比“三个月压缩成一条
真实轴”更适合阅读：一天约 12px，1–3 天的会话仍有可见长度。拖动是平移画布，不是修改会话时间。

## 已观察到的取舍

- **P1** 最像“时间线”的观感，读起来也最轻松；但竖线只是装饰，不回答“隔了多久、覆盖多长”。
- **P2** 能在一屏里看到会话覆盖与相对位置，左右拖动可回看 7–10 月；固定 30 天让每月等宽，31 日被压到
  月末，所以它不是精确日历，适合“看趋势”，不适合“查某天”。
- **P3** 能比较跨度长短（1 天 vs 5 天），但条都从左侧开始，表达的是“长度”不是“位置”；
  若要看重叠，仍需要另一条轴。
- **P4** 能看出“聊了两天、停了一天又回来”，比连续条更诚实；但视觉更碎，且点之间的空白没有时间比例。
- 三者（P1/P3/P4）在 480px 都会退化成“左侧竖线 + 单列卡片”，左右交替只在宽屏成立；P2 在窄屏
  保留横向拖动，左侧标题列收窄到 136px。

## 还需要定的事

1. 时间轴方向：最新在上（与列表一致）还是最早在上（时间轴习惯）；
2. 轴的比例：固定 30 天月轴、月带压缩、等距，还是真实比例；
3. 覆盖语义：连续首末跨度，还是按活跃日点串；
4. 时间轴是第二个视图（`列表 | 时间轴`），还是替换列表。当前建议：保留列表，时间轴作为第二视图。

看过 P1–P4 之后再定 1 和 2；在这之前不改正式页面的数据与交互。
