# 使用指南

[返回 README](../README.md)

## 安装与首次启动

当前主要验证环境是 Windows、Edge、Node.js 24.x 与 Python 3.11。其他系统可以运行相关工具，但尚不代表所有桌面行为都经过同等验证。

在仓库根目录执行：

```powershell
npm install
python -m pip install pypdfium2 openpyxl
npm run library
npm run dev -- --host 127.0.0.1 --port 5173
```

打开 http://127.0.0.1:5173/。`library` 从已有归档生成完整应用；没有归档时也能生成空页面，不必先准备 JSON 或测试样本。

### Python 与浏览器

- TXT、DOCX 预览使用 Python 标准库；PDF 需要 `pypdfium2`，XLSX 需要 `openpyxl`。
- Python 选择顺序为 `CEOBE_PYTHON`、系统 Python，再尝试开发环境中的后备运行时。普通用户应保证前两者之一可用。
- Windows 归档默认使用已安装的 Edge。其他平台可安装 Chromium：

```powershell
npx playwright install chromium
```

需要指定其他已安装浏览器或 Python 时，可设置环境变量，例如 PowerShell：

```powershell
$env:CEOBE_PYTHON = 'C:\path\to\python.exe'
$env:CEOBE_BROWSER_CHANNEL = 'msedge'
```

归档浏览器独立运行，不读取个人浏览器配置。浏览器不可用或附件未向分享页开放时，仍会记录缺失情况，不保证附件完整。

## 运行模式

| 模式 | 用途 | 能力 |
|---|---|---|
| 本地开发服务 | 日常使用、开发调试 | 导入、管理、阅读及即时导出 |
| 本地生产服务 | 使用构建后的应用 | 同样支持本地 API 和写入 |
| 纯静态服务 | 分发或查看构建时快照 | 阅读已生成页面，不支持本地写入和即时导出 |

运行生产版本：

```powershell
npm run library
npm run build
npm run preview
```

访问终端显示的本地地址。开发服务通常使用 5173 端口，生产预览通常使用 4173 端口。

重启电脑后，如果归档和生成页面没有变化，通常只需重新运行 `npm run dev` 或 `npm run preview`。导入会自动更新页面，不需要每次手动构建。

**不要在导入、删除或其他写入过程中另外运行手动构建。** 本地服务应保持回环地址监听，不建议未经额外访问控制就暴露到公网。

## 保存第一条对话

1. 准备你有权保存的 ChatGPT 分享链接。分享本身可能扩大内容的可访问范围，请先检查隐私。
2. 打开“导入会话”，粘贴 `https://chatgpt.com/share/…` 链接并提交。
3. 等待归档和页面更新，检查完成提示及资源缺失说明。提示中的“轮对话”是阅读页实际显示的问答气泡数；“归档记录”是分享数据里的全部节点数，还包含隐藏的系统上下文、推理过程和联网搜索等工具活动，因此通常明显多于轮数。
4. 从侧栏打开聊天，或通过聊天菜单将它移至项目。

在项目详情页导入时，新归档会关联到该项目。如果归档成功但关联或生产发布失败，可按提示重试；已有的归档不会因为发布失败而被删除。

同一分享链接可有多个历史抓取版本。档案库默认显示最新一份可读取的记录，旧版本不会因为再次导入自动消失。

## 阅读与整理

### 阅读

- 支持正文、代码、公式、表格、图片及受支持附件的本地展示。
- 再次打开同一聊天时会回到上次阅读的那条消息，并在右下角短暂显示“已回到上次阅读位置 · 第 N 轮”，可跳到该条消息、从头阅读或关闭提示；按聊天分别记录，只保存在本机浏览器，仅存稳定消息 ID 与条内偏移，不写入归档、不含消息内容，也不会自动加书签。刚刚读取的位置不再重复提示。
- “更多 → 查看聊天中的文件”打开文件和来源面板，可搜索其中的条目。
- 图片使用遮罩查看器，关闭按钮、Esc 或点击遮罩可关闭；没有额外的缩放工具栏。
- 网页引用仍是外部链接；点击它们可能离开本地阅读器，并需要联网。

附件预览覆盖 TXT、Markdown、日志、CSV、JSON、DOCX、PDF 和 XLSX。PDF 显示页面图片，暂不支持从预览中选择文字；XLSX 支持只读工作表切换，不是电子表格编辑器。未下载或未支持预览的文件会保留相应状态，不替换为演示附件。

表格预览的几点行为：

- **点单元格**会高亮它所在的行与列（再点一次取消），读宽表时不容易串行；右侧缩放条可以在 50%–200% 之间调整，点「重置」回到 100%；
- 原表里**隐藏的行或列**照常显示，但会变淡并带提示，避免误以为没有隐藏；
- **大表只预览前 500 行 × 60 列**（`CEOBE_SHEET_MAX_ROWS` / `CEOBE_SHEET_MAX_COLS` 可调），表格上方会注明原表规模，完整内容请下载原文件；
- 合并单元格、数字格式（金额/百分比/日期）、字体与填充色、列宽行高都会保留。

折叠侧栏后的“最近聊天”支持上下键切换聊天、左右键切换行内置顶／更多操作，Tab／Shift+Tab 按顺序移动；在首尾边界继续 Tab 会退出菜单，Esc 关闭并返回入口。

### 书签与个人备注

当前先以定位为主、备注为辅，后续再逐步加强备注整理能力。

- 在用户消息或助手回复的“更多操作”中选择“添加书签”。每条消息只保留一个书签；已有书签可再次编辑。
- 标题默认取消息摘要，可修改，最多 160 个字符；个人备注可留空，最多 20000 个字符。点击保存才写入，取消或 Esc 放弃当前修改。
- 聊天正文左侧的书签按钮展开当前聊天列表，按消息顺序排列，可随时收起。列表在正文左侧悬浮显示，展开或收起都不改变中间聊天区域的位置和宽度；列表不会锁住正文，点击定位后保持打开。阅读区底部“书签与备注”也可打开该列表。
- 正文左侧的空白足够放下列表时，列表停靠在空白内并保持打开；空白放不下时改为最高约 420 像素的短浮层，点击浮层之外任意位置即自动收起，按 Esc 同样收起，窄窗口下不会出现挡住正文的整列面板。从浮层点进编辑窗不算“点外面”：点「取消」会回到列表，保存或删除后按结果继续；列表为空或搜索没有结果时只显示一行提示，不拉出整列空白。
- 消息旁的书签按可用空间依次显示图标、标题、标题与短摘要；完整备注仍可点击打开。旁边连图标也放不下时，图标移至消息边缘的独立位置，不挤压成竖排或遮住正文。缩窄窗口会收起已展开的摘要，不会修改备注内容。
- 侧栏“更多 → 全部书签”查看跨聊天列表，按最近编辑排列；只搜索书签标题和当前聊天标题，不搜索正文或备注。
- 目录与书签均跳到目标消息顶部，并避开固定页头；书签定位后短暂高亮原消息。助手的多个归档记录可能合并显示在同一个回复块中，此时定位到包含原消息的回复块，而不是按临时渲染序号寻找。
- 聊天改名或移动项目不改变书签。重新归档后，只要稳定消息 ID 仍在当前展示记录中就可定位；目标缺失时明确提示，不跳到相邻消息。失效书签的备注仍可查看、编辑或删除。
- 当前聊天列表省略重复的聊天来源，标题前用用户／GPT 图标区分消息；全局列表保留聊天名称。备注预览最多两行，第二行右端固定保留编辑图标，超出部分以 `...` 截断；打开编辑窗可查看完整备注，保存内容不被截短。
- 删除书签需在编辑窗再次确认，不影响聊天。并发修改或保存失败时保留草稿，不静默覆盖；冲突后请先复制草稿，再关闭编辑窗并重新打开合并。
- 备注独立保存在 `data/private/bookmarks.ceobe.json`，不改原消息，不写入派生 HTML、聊天 MD 或项目 ZIP。需要本地开发或生产服务读取和保存；纯静态页面不携带个人书签快照。
- 阅读区不提供 AI 续聊、听写或语音，也不执行原站的消息操作：消息工具条只保留「复制」和「更多操作 / 编辑书签」，
  编辑消息、评价回复、单条分享、模型切换以及生成图片的喜欢／不喜欢、图片悬浮层都不出现在页面上；
  没有可复制正文的回复（生成图片、图表）连复制按钮也不显示。点赞不会被改作书签。

### 时间

侧栏「项目」和「更多」之间的「时间」（时钟图标）打开按时间排列的档案。页内有两个视图：

- **时间线**（默认）：按年／月分组，最新月份在前；每行两行式：标题在上，第二行是这条会话
  首条→末条可见消息的时间与对话轮次；工具栏可切「列表 / 卡片」：
  - **列表**：密度高，适合快速扫读；
  - **卡片**：两列等高卡片（224px）；标题旁显示轮数，模型在右上；摘要 4 行，tag 在摘要之后占整行；
    底栏一行显示「用户输入：… 模型输出：… 活跃天数：…」，活跃条在右下角。tag 最多 6 个，超出用 `+N`。
    摘要和 tag 没有数据时不占位；布局选择会记住。
- **时间轴**：上方是真实日历缩略图（7px/天、3 条泳道、视口框），下方是详情（96px/天、白色标题卡）；
  滚动详情会同步视口框，点击/拖动缩略图定位详情，视口框可用方向键/Home/End 移动。

时间线的细节：

- 月份标题滚动时吸顶，右侧显示当月会话数与对话轮次；页首显示总会话与总对话轮次，并标明「本地时间」；
- 顶部「按首条消息」可切换「最新在前 / 最早在前」，选择会记住（`localStorage`），月份与月内条目一起反转；
- 时间统一为 `M月D日 HH:mm`：同一天是 `起–止`，跨天是 ` - `，跨年带年份；
- 点击跳到会话页，并定位、高亮它的首条可见消息；
- 只用消息自己的时间；索引记录构建机的 IANA 时区，列表、卡片、时间轴都按该时区显示，
  换到别的时区浏览器也不会偏移；会话的 `created_at` 是分享链接创建时间，不参与排序；
  隐藏记录、推理和工具往来不计入，所以“时间线”就是阅读页看到的内容；
- 索引同时保留 `turns`（用户轮 + 助手轮的可见轮次）和 `rounds`（用户轮，界面称“对话轮次”）；
  例如 `03查看文件内容` 是 35 轮对话、70 个可见轮次。界面只显示前者，后者用于 tooltip/审计。
- 卡片底栏的模型、字数和活跃来自索引：多模型只显示主模型；字符是可见用户/助手正文的
  非空白字符数，精确值在 tooltip；摘要和 AI tag 是同一份可选元数据。
- 活跃条按日轮次分三档：1–10 浅绿、11–50 中绿、51+ 深绿，无消息留白；tooltip 给出当天轮次。
- 摘要和 AI tag 来自 `timeline-summaries.json`；tag 最多显示 6 个，超出用 `+N`；1.2 只搭骨架，不生成。
- 索引在 `npm run library`（含导入后的重建）时生成；缺失时会提示重建。重命名只更新 `chats.json`，
  不需要重建时间线索引。
- 视图切换写在 URL（`?view=axis`）和 `localStorage`；分享/刷新后保持。

### 搜索、置顶与项目

- 搜索覆盖本地聊天标题和正文，包括置顶和项目内聊天。标题命中列在“搜索结果”，正文命中列在下方的“正文命中”，每条显示所在聊天、命中片段及“用户／GPT · 第 N 轮”；点击即跳到该条消息并高亮（与书签定位相同）。正文索引在 `npm run library`（含导入后的重建）时生成，只包含阅读页可见的提问、最终回复和代码，不含推理过程、引用来源、附件内容和书签备注；正文命中最多显示 50 条，索引不可用时自动退回仅按标题搜索并在状态文字中说明。
- 搜索框支持语法：`"精确短语"`（引号内空格不拆词）、`-排除词`、`A/B`（任一命中）、`title:词`（只筛标题）、`from:user|gpt`（只筛正文角色）、`has:code|table|image|attachment`（只筛带该类型的回复）、`created:2025-06`（聊天创建时间，可写 `>`、`>=`、`<`、`<=`）与 `messages:>20`（阅读轮数）。同一词内的 `/` 表示任一（`from:`／`has:`／`created:`／`messages:` 也一样），词与词之间是“且”；`title:` 只影响标题列表，`from:`／`has:` 只影响正文命中，`-词` 同时排除标题与正文命中；只有排除词时不列正文。
- 语法细节：URL 里的 `/` 不当作“任一”分隔符，需要字面斜杠时写 `\/`；`-1` 这类负数是普通文本，不当排除；无法识别的 `字段:值`（例如 `region:eu`）按普通文本搜索，旧查询结果不变。空结果文案会提示可去掉的条件。`has:` 的类型标签来自正文索引，升级后需重建一次阅读页才会生效。
- 聊天可置顶／取消置顶，或移至已有项目。按项目整理时，置顶聊天同时保留在顶部置顶区和所属项目中；项目内使用右侧置顶标记，取消置顶不会改变项目归属。
- 每条聊天的侧栏菜单和阅读顶部“更多”菜单都会在 MD 导出项旁边显示“打开本地文件夹”，在 Windows 资源管理器中打开这条聊天当前使用的本地归档快照目录（`archive/chatgpt-share/<聊天 ID>/<抓取时间>/`，内含 `conversation.md`、附件等）。此项需要本地开发或生产服务；只打开静态 HTML 或在非 Windows 系统上会提示无法打开。
- 顶部置顶聊天的项目名靠右显示并限制最大占宽，优先给聊天标题留空间；长项目名省略，悬停可查看全名。
- 从聊天的“移至项目 → 新项目”创建，会自动移入当前聊天；原侧栏“项目”行的“＋”只创建项目，不隐式移动聊天。
- 项目标题可直接点击重命名，也可以从侧栏项目菜单操作。
- 项目简介在设置内编辑，最多 4000 个字符。点击“保存简介”生效，关闭或 Esc 放弃未保存修改；冲突或失败时保留草稿，不直接覆盖其他窗口的更新。
- 新建项目时可以选择图标与颜色；已有项目可通过“项目设置”点击图标，复用同一选择器编辑，点击“完成”保存到本地。
- 支持预设颜色与 `#RRGGBB` 自定义颜色。Esc 或点击选择器遮罩取消未保存的选择；图标／颜色与项目简介分别保存。
- 保存后侧栏、项目详情、项目列表及移动菜单读取最新外观，刷新后保留。只读状态不允许修改；保存失败保留选择，并发冲突需关闭整个项目设置后重新打开，避免覆盖其他窗口。

侧栏收起、按列表／项目整理、分组展开等偏好保存在当前浏览器中，不更改聊天归档。

在会话之间切换时，侧栏会保持完整列表、滚动位置和当前活动项；从时间线等顶层页第一次进入会话仍是正常整页加载。首次打开页面时侧栏目录仍需从本地 `chats.json` 或 `/api/chats` 加载。

Windows 快捷键：`Ctrl+K` 搜索（标题和正文，支持 `title:`／`has:` 等语法），`Ctrl+Shift+S` 开关侧栏，`Ctrl+Shift+O` 进入导入会话。

### 项目文件：自动汇总项目聊天附件

进入项目详情的“文件”标签，查看本项目聊天中的文件和图片。界面复用资料库的搜索、分类、排序、预览和下载方式，不需要手动添加或解除关联。

- 只统计当前项目的聊天。同一内容的文件去重显示，并保留它在当前项目中的来源聊天链接；项目外聊天不出现在这些链接或搜索范围里。
- 文件名称、别名和归档时间取自项目内的来源记录，来源聊天标题使用当前本地名称。
- 可按文件名或来源聊天标题搜索，使用“全部／图片／文件”分类，并按名称、归档时间、大小排序。
- 点击文件名打开预览，可下载原文件或返回来源聊天。未保存的附件仍显示记录和状态，不提供虚假预览或下载。
- 聊天移入／移出项目、导入或删除后重新统计；切回窗口或刷新也会更新。统计过程只读，不复制、移动或删除原文件。
- 项目没有附件时显示空状态，不用全局资料库内容填充。服务不可用时仅显示构建时的项目快照并明确提示，不能保证关联为最新。
- 旧“来源”的手动关联字段保留在本地，但不参与文件统计，旧添加／解除关联接口已停用。旧 `tab=sources` 地址兼容跳转到 `tab=files`。

项目文件不加入聊天 MD 或项目 ZIP，导出继续保持纯文本语义。

### 删除前请确认

- **删除项目**：只删除项目及关联，全部聊天、书签备注、附件和历史归档保留，聊天回到未归属状态。
- **删除聊天**：永久删除该聊天的全部归档版本、相关项目关联、该聊天的全部书签与备注及派生页面。其他聊天的独立附件副本保留。

永久删除不是隐藏条目；重要内容请先备份。

## 资料库的视图与筛选

- 右上角可切换 **列表 / 网格**（选择会记在本机，下次打开保持）；
- 网格是卡片式，适合看图片缩略图；列表保留名称、归档时间、大小三列，便于比对；
- 搜索框下方新增两个筛选：**来源会话**（按产生该附件的聊天过滤）与**保存状态**（已保存 / 未保存），
  可与顶部"全部 / 图片 / 文件"和搜索关键词叠加使用；
- 表格表头只在列表模式显示，网格模式下自动隐藏。

### 文件夹就是标签

- 资料库里的**文件夹等于标签**：一条资源可以同时属于多个文件夹，资源本身的位置不变；
- 点文件夹条上的名字只看这个文件夹里的资源，点「全部」回到完整列表；搜索会同时匹配文件名、来源会话和文件夹名；
- 「管理文件夹」里可以新建、重命名、删除文件夹。**删除文件夹只删标签**，不会删除任何资源或文件；
- 打开任意一条资源的预览窗，底部会列出全部文件夹，点一下即加入、再点一下移除（立即保存）；
- 文件夹与标签保存在 `data/private/library.ceobe.json`。纯静态页面也能按文件夹筛选（构建时写入），
  但新建、改名、打标签和上传需要本地服务。

### 上传自己的文件

- 资料库右上角「上传文件」可以一次选多个文件；它们列在同一个列表里，可以预览、打标签、下载；
  文本类（Markdown、TXT、CSV、JSON 等）在预览窗里直接显示内容，图片直接显示，其他类型提供下载；
- 上传的字节保存在 `data/private/library-files/`，**不写进 `archive/`**（那里只放采集来的原始档案）；
- 「从资料库移除」只移除这条记录（要点两次确认），**磁盘上的文件不会被删除**；
  需要真正删除文件请手动处理 `data/private/library-files/`；
- 同一份内容重复上传只保留一条记录（按内容 sha256 去重）。

## 导出

### 浏览器扩展：直接归档

不装扩展也可以只用网页导入；装了扩展可以省掉「下载 ZIP → 拖进页面」两步：

1. `edge://extensions/`（或 `chrome://extensions/`）打开开发人员模式，加载 `extension/` 目录；更新文件后点扩展卡片上的「重新加载」；
2. 先运行 `npm run dev`（或 `npm run preview`），点扩展图标 →「检测」找到本地服务（默认 `http://127.0.0.1:5173`，端口不同也可以手填）；
3. 在 `chatgpt.com/share/…` 页面右下角点「发送到 CEOBE」，或在 popup 里粘贴链接点「发送到本地 CEOBE」。

- 抓取是匿名的（`credentials: 'omit'`、不跟随重定向），附件仍由本地管线发现和下载；
- 没有本地服务时，用 popup 里的「导出 ZIP」把采集包下载下来，再拖到导入输入框；
- 不装扩展时，用 `extension/bookmarklet.md` 里的书签小工具：点一下打开本地导入页并预填链接（不跨站 POST）；
- 采集包带 `format`/`version` 握手：0.4.x 的旧 ZIP 仍可导入；比本地支持更高的版本会明确提示更新，不会带着半个包解码；
- 本地服务只放行扩展 scheme（`chrome-extension://` 等）的跨源请求，普通网站仍受同源与 `Sec-Fetch-Site` 检查保护；
- 如果提示「采集包已归档，但页面更新失败」，快照其实已经保存，只是页面没更新：运行 `npm run library`
  或再点一次发送（不会重复导入）。

### 批量导入分享链接

在「导入会话」的输入框里**一次粘贴多条** `https://chatgpt.com/share/…` 链接（每行一条），提交后会：

- 依次抓取、解码、归档，每条完成后继续下一条；两次抓取之间至少间隔 1.5 秒，每 40 条会强制休息 30 秒；
- 同一条链接写两次会被自动去重；
- 全部结束后汇总「成功 N 条 / 失败 M 条」，失败项列在原位，成功项可点「打开最后一条」；
- 单条失败不会中断其余链接；
- **被限流时会自动暂停整批**：连续 3 次返回 429/503，或最近 10 条里失败率超过 60%，服务端会停掉这一批并回一个「建议 X 分钟后再试」；
  界面上会提示「批量导入已暂停」，**没处理完的链接会留在输入框里**，等一会儿原样再提交即可（已归档的会自动跳过）；
- 批量模式只在「导入会话」页可用，项目页仍按单条导入。

### 单条聊天：Markdown

阅读顶部或聊天菜单的“另存为 MD”生成 `当前聊天标题.md`。

- 文件以 **YAML frontmatter** 开头：`title / chat_id / url / project / created / updated / model / tags`
  （只写真正知道的字段，例如没有归入项目就不写 `project`）；
- 公式定界符从官方的 `\( \)` / `\[ \]` 转成 Obsidian 认识的 `$…$` / `$$…$$`（代码块与行内代码里的内容不动，
  货币写法 `$5` 会转义成 `\$5`）；
- 文末自动生成 `## Sources`：把网页引用按去重后的顺序列成编号链接；没有引用时不生成这一节；
- 保留正文、代码、公式和表格等文本表达；图片、附件和普通链接转为可读文字，不复制资源文件；
  代码示例中的链接语法保持原样。

需要**连同附件一起**导出（Obsidian 可直接打开）时用命令行版本：

```powershell
npm run export:md -- --all --out D:\vault\ceobe              # 整个档案库
npm run export:md -- --id <会话 ID> --out D:\vault\ceobe      # 只导一条
npm run export:md -- --all --out D:\vault\ceobe --no-assets   # 只要文本
npm run export:md -- --all --out D:\vault\ceobe --link-style wikilink
```

- 每条聊天写成 `<标题>.md`，附件复制到 `<out>/attachments/`，正文里的链接改成相对路径
  （`--link-style wikilink` 时改成 `![[文件名]]`，适合 Obsidian）；
- 同名附件不会互相覆盖：内容不同时后一个会带上内容哈希后缀；
- 标题重复时会自动编号；`--no-assets` 等价于“纯文本”，不写附件链接也不复制文件；
- 只读 `archive/`，只往 `--out` 写；`--all` 会跳过不存在的会话并在结束时列出写出的文件。


### 整个档案：官方格式 JSON

把本地档案导出成 ChatGPT 官方 `conversations.json` 的字段形状，方便喂给其它工具（导入器、分析脚本、MCP 客户端）：

```powershell
npm run export:json -- --all --out D:\ceobe-export
npm run export:json -- --id <会话 ID> --out D:\ceobe-export
npm run export:json -- --all --out D:\ceobe-export --no-assets   # 只写 JSON
npm run export:json -- --all --out D:\ceobe-export --compact      # 单行 JSON
```

- 产物：`conversations.json`（`--all` 与多个 `--id` 为数组；单个 `--id` 为对象）、`attachments/<sha256>.<ext>`、`manifest.json`；
- 字段按官方格式：`title / create_time / update_time / conversation_id / current_node / mapping`，
  `mapping[node]` 为 `{id, parent, children, message}`；消息的 `content` 直接使用归档里的原始内容对象，
  不做 LaTeX／Markdown 改写，也不伪造 `file-service://` 链接；
- 扩展字段 `ceobe`：来源（url／抓取时间）、`linear_message_ids`、隐藏消息清单、资源本地路径、`import_report`；
  重命名过的聊天把原标题写进 `ceobe.original_title`；`raw_payload` 不导出；
- 附件默认按内容哈希复制（相同内容只存一份），`--no-assets` 关闭复制并把 `ceobe.resources[].local_path` 写成 null；
- 同一份输入导出两次逐字节一致（不写墙钟时间）；`manifest.json` 记录格式版本、会话／消息／节点／隐藏消息数、
  附件复制／缺失／跳过数与 `conversations.json` 的 sha256；
- 只读 `archive/`，只写 `--out`；来源没有提供或获取失败的附件不会伪造，只计入清单的“缺失”数；
- 实测：34 个会话导出 `conversations.json` 64.6 MB；带附件时另加 249.3 MB／321 个文件，整体约 7 秒；
  153 个资源因未下载而缺失（146 个 unresolved、7 个 failed）。


### 单条聊天：PDF

```powershell
npm run dev                                    # 另开一个窗口，保持运行
npm run export:pdf -- --id <会话 ID>
npm run export:pdf -- --id <会话 ID> --mobile --document   # 手机尺寸 + 文档版式（实验）
npm run export:pdf -- --id <会话 ID> --mobile   # 手机尺寸（100×178mm，紧凑排版）
npm run export:pdf -- --all            # 批量导出整个档案库
# → data/private/pdf/<会话 ID>.pdf
```

- A4、上下 16mm / 左右 14mm 页边距，导出的是**只有正文**的版本：不带浏览器页眉页脚（`127.0.0.1` 地址就是这么来的）、不带分享按钮；
- 中文使用微软雅黑等黑体族，不会退回新宋体；表格在版心内换行，长代码行在代码框内折行；
- 如果直接按 `Ctrl+P` 打印，页眉页脚由浏览器对话框控制，需要在弹窗里**手动取消勾选**"页眉和页脚"；
- `--mobile` 输出到 `data/private/pdf-mobile/`：100×178mm、12px/1.55 紧凑排版，实测一条 342 页的 A4 文档在手机尺寸下为 **278 页 / 4.6 MB**（页边距 5mm，同样可读）；
- 文档版式导出后会用 `scripts/pdf-stamp.py` 在**第 1 页顶部**盖页眉（会话标题 + 导出日期），并在**每页底部**加页码 `N / 总数`；这段空间原本是版式留白，画不进 DOM，只能导出后盖章；
- `--document` 是实验性的文档版式：用户消息左对齐、去掉气泡底色、隐藏书签与复制等聊天装饰，输出到 `data/private/pdf-document/`；实测同一条会话 270 页（聊天版式 272 页）；
- 导出后可以运行 `npm run audit:pdf` 自检：会报告总页数、字体、越界页与短页；越界会返回非零。
- 导出依赖本地服务（`npm run dev`），因为要读取 `/conversations/<id>.html`。批量模式默认跳过已存在的文件（加 `--force` 重导），结束时会汇总页数与体积。

### 整个项目：ZIP

项目“另存为 ZIP”生成 `项目名称.zip`，内部每条聊天对应一个 `聊天标题.md`。

- 重复文件名自动编号，也处理大小写与 Unicode 兼容形式的冲突。
- 不包含附件、项目简介、项目文件、书签备注或完整消息树。
- 空项目可生成空 ZIP；存在缺失聊天时拒绝生成残缺包。
- 当前上限为 65,535 个文件、200 MiB 未压缩文本。

### 保存位置

受支持的 Edge／Chromium 安全上下文优先显示原生保存窗口。没有该接口时回退普通下载，保存位置由浏览器设置决定。取消原生保存不会开始读取导出内容；写入失败会提示，而不是报成功。

浏览器接口模拟与下载回退已经自动化测试；实际 Windows 保存窗口的目录选择、保存位置、取消与同名覆盖也已在使用者环境中验收通过。

## 数据与备份

| 路径 | 内容 | 是否需要备份 |
|---|---|---|
| `archive/` | 聊天原始响应、规范化 JSON、历史抓取、附件及报告；`archive/chatgpt-share/README.md` 是自动生成的“标题 ↔ 聊天 ID”索引，方便在磁盘上按标题找到 ID 命名的文件夹 | 是 |
| `data/private/` | 项目、简介、书签备注、聊天显示元数据、任务与恢复记录；也可能有私人开发捕获 | 是，按敏感数据保护 |
| `attachments/private/` | 若存在，本地私人附件 | 是 |
| `replay/`、`dist/` | 派生阅读页面与生产构建 | 可重建，不能替代源数据 |

建议等所有操作完成，停止本地服务后再复制备份，避免取得一半新、一半旧的状态。恢复到匹配的项目版本后，可用 `npm run library` 重新生成页面，再按需执行 `npm run build`。

浏览器里的折叠、排序等界面偏好不随这些目录一并迁移。MD／ZIP 导出也不是完整备份。

本地数据目录默认不纳入 Git，但截图、日志和手工复制的文件仍可能包含隐私，提交前应自行检查。

## 常见问题

### 导入或资源不完整

检查归档的 `import-report.json` 与资源状态。“结构检查通过”不代表所有附件都已下载。分享页面未提供的消息、受限附件及外部应用内容无法保证恢复；引用网站不会被递归保存。

### 导入失败后没有留下快照

分享链接抓取失败（链接失效、被作者删除、网络中断、页面无法解码）时，默认**不会**在 `archive/` 里留下快照，
连空的会话目录也会一并删除——避免档案里出现打不开的假条目。

需要排查原始页面时，用命令行加 `--keep-failed` 保留：

```powershell
npm run archive:share -- https://chatgpt.com/share/<share-id> --keep-failed
```

保留的快照里会有 `capture.json`、原始 `raw/share.html`，解码失败时还有 `import-error.txt`。
确认问题解决后，这属于诊断快照，可以按需清理；正常导入不会进入这条路径。

### 只读提示、导入或导出不可用

确认正在使用本地开发或生产服务，而不只是打开静态 HTML。还应检查终端错误、网络连接、Python 和归档浏览器是否可用。

### 页面没有反映手动修改的归档

确保没有正在执行的写入操作，再运行 `npm run library`。生产模式随后运行 `npm run build`。不要使用演示命令代替档案库重建。

### 异常退出后提示工作区正在写入

`data/private/mutation.lock` 以及 `data/private/delete-jobs/*/journal.json` 可能记录未完成操作。先确认进程状态和恢复记录，**不要为了消除提示直接删除锁文件或恢复目录**。导入、项目与书签写入、聊天删除使用同一工作区锁。

### 删除后的 archive 恢复

每次永久删除会话前，会在 `data/private/archive-backups/` 下生成一份完整的 archive 快照：

```text
data/private/archive-backups/<时间>-<会话短 id>-<随机后缀>/
  manifest.json
  archive/
```

这份快照不随 `delete-jobs` 清理，也不会自动删除；多次删除就是多代快照。也可以随时手动创建一份（不删除任何内容）：

```powershell
npm run archive:backup
```

恢复单个会话时，先停止本地服务，再把快照中的目录复制回：

```powershell
Copy-Item "data/private/archive-backups/<快照>/archive/chatgpt-share/<会话 id>" `
  "archive/chatgpt-share/<会话 id>" -Recurse
npm run library
```

恢复整个 `archive/` 时，先把当前目录改名留底，再复制快照的 `archive/`，然后运行 `npm run library` 和 `npm run build`。
快照使用硬链接，能防止误删，但不能防止整块磁盘损坏；重要档案仍应另外复制到另一块盘或外部备份。

## 命令行与演示

以下是高级入口，不是首次使用的必经步骤。执行会重建页面的命令前，请确认本地服务没有写入任务。

```powershell
# 直接归档分享链接，成功后更新档案库
npm run archive:share -- https://chatgpt.com/share/<share-id>

# 排查导入失败：保留原始页面与错误信息（默认失败不落盘）
npm run archive:share -- https://chatgpt.com/share/<share-id> --keep-failed

# 重建档案库，并选择默认首页
npm run library -- --select <share-id>

# 只重建指定聊天的阅读页；首页与共享样式不动，多个 id 用逗号分隔（不写入 archive/，索引按现状读取）
npm run library -- --only <share-id>[,<share-id>…]

# 从单个 CEOBE JSON 生成阅读页面，不等同于完整档案库入口
npm run replay -- --input path/to/conversation.ceobe.json

# 显式启用测试样本演示；不会删除原始档案，但会替换派生页面
npm run replay:sample

# 从演示或单 JSON 回放回到真实档案库
npm run library
```

导入保存的分享 HTML 的底层工具：

```powershell
npm run import:share -- path/to/share.html --output path/to/conversation.ceobe.json
```

该工具生成 JSON；完整链接归档、资源下载和档案库更新请使用分享链接归档流程。详见[架构说明](architecture.md)。
