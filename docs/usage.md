# 使用指南

[返回 README](../README.md)

## 安装与首次启动

当前主要验证环境是 Windows、Edge、Node.js 24.x 与 Python 3.11。其他系统可以运行相关工具，但尚不代表所有桌面行为都经过同等验证。

在仓库根目录执行：

```powershell
npm install
python -m pip install pypdfium2 openpyxl
npm run library
npm run dev -- --host 127.0.0.1 --port 5173
```

打开 http://127.0.0.1:5173/。`library` 从已有归档生成完整应用；没有归档时也能生成空页面，不必先准备 JSON 或测试样本。

### Python 与浏览器

- TXT、DOCX 预览使用 Python 标准库；PDF 需要 `pypdfium2`，XLSX 需要 `openpyxl`。
- Python 选择顺序为 `CEOBE_PYTHON`、系统 Python，再尝试开发环境中的后备运行时。普通用户应保证前两者之一可用。
- Windows 归档默认使用已安装的 Edge。其他平台可安装 Chromium：

```powershell
npx playwright install chromium
```

需要指定其他已安装浏览器或 Python 时，可设置环境变量，例如 PowerShell：

```powershell
$env:CEOBE_PYTHON = 'C:\path\to\python.exe'
$env:CEOBE_BROWSER_CHANNEL = 'msedge'
```

归档浏览器独立运行，不读取个人浏览器配置。浏览器不可用或附件未向分享页开放时，仍会记录缺失情况，不保证附件完整。

## 运行模式

| 模式 | 用途 | 能力 |
|---|---|---|
| 本地开发服务 | 日常使用、开发调试 | 导入、管理、阅读及即时导出 |
| 本地生产服务 | 使用构建后的应用 | 同样支持本地 API 和写入 |
| 纯静态服务 | 分发或查看构建时快照 | 阅读已生成页面，不支持本地写入和即时导出 |

运行生产版本：

```powershell
npm run library
npm run build
npm run preview
```

访问终端显示的本地地址。开发服务通常使用 5173 端口，生产预览通常使用 4173 端口。

重启电脑后，如果归档和生成页面没有变化，通常只需重新运行 `npm run dev` 或 `npm run preview`。导入会自动更新页面，不需要每次手动构建。

**不要在导入、删除或其他写入过程中另外运行手动构建。** 本地服务应保持回环地址监听，不建议未经额外访问控制就暴露到公网。

## 保存第一条对话

1. 准备你有权保存的 ChatGPT 分享链接。分享本身可能扩大内容的可访问范围，请先检查隐私。
2. 打开“导入会话”，粘贴 `https://chatgpt.com/share/…` 链接并提交。
3. 等待归档和页面更新，检查完成提示及资源缺失说明。提示中的“轮对话”是阅读页实际显示的问答气泡数；“归档记录”是分享数据里的全部节点数，还包含隐藏的系统上下文、推理过程和联网搜索等工具活动，因此通常明显多于轮数。
4. 从侧栏打开聊天，或通过聊天菜单将它移至项目。

在项目详情页导入时，新归档会关联到该项目。如果归档成功但关联或生产发布失败，可按提示重试；已有的归档不会因为发布失败而被删除。

同一分享链接可有多个历史抓取版本。档案库默认显示最新一份可读取的记录，旧版本不会因为再次导入自动消失。

## 阅读与整理

### 阅读

- 支持正文、代码、公式、表格、图片及受支持附件的本地展示。
- “更多 → 查看聊天中的文件”打开文件和来源面板，可搜索其中的条目。
- 图片使用遮罩查看器，关闭按钮、Esc 或点击遮罩可关闭；没有额外的缩放工具栏。
- 网页引用仍是外部链接；点击它们可能离开本地阅读器，并需要联网。

附件预览覆盖 TXT、Markdown、日志、CSV、JSON、DOCX、PDF 和 XLSX。PDF 显示页面图片，暂不支持从预览中选择文字；XLSX 支持只读工作表切换，不是电子表格编辑器。未下载或未支持预览的文件会保留相应状态，不替换为演示附件。

折叠侧栏后的“最近聊天”支持上下键切换聊天、左右键切换行内置顶／更多操作，Tab／Shift+Tab 按顺序移动；在首尾边界继续 Tab 会退出菜单，Esc 关闭并返回入口。

### 书签与个人备注

当前先以定位为主、备注为辅，后续再逐步加强备注整理能力。

- 在用户消息或助手回复的“更多操作”中选择“添加书签”。每条消息只保留一个书签；已有书签可再次编辑。
- 标题默认取消息摘要，可修改，最多 160 个字符；个人备注可留空，最多 20000 个字符。点击保存才写入，取消或 Esc 放弃当前修改。
- 聊天正文左侧的书签按钮展开当前聊天列表，按消息顺序排列，可随时收起。列表在正文左侧悬浮显示，展开或收起都不改变中间聊天区域的位置和宽度；列表不会锁住正文，点击定位后保持打开。阅读区底部“书签与备注”也可打开该列表。
- 消息旁的书签按可用空间依次显示图标、标题、标题与短摘要；完整备注仍可点击打开。旁边连图标也放不下时，图标移至消息边缘的独立位置，不挤压成竖排或遮住正文。缩窄窗口会收起已展开的摘要，不会修改备注内容。
- 侧栏“更多 → 全部书签”查看跨聊天列表，按最近编辑排列；只搜索书签标题和当前聊天标题，不搜索正文或备注。
- 目录与书签均跳到目标消息顶部，并避开固定页头；书签定位后短暂高亮原消息。助手的多个归档记录可能合并显示在同一个回复块中，此时定位到包含原消息的回复块，而不是按临时渲染序号寻找。
- 聊天改名或移动项目不改变书签。重新归档后，只要稳定消息 ID 仍在当前展示记录中就可定位；目标缺失时明确提示，不跳到相邻消息。失效书签的备注仍可查看、编辑或删除。
- 当前聊天列表省略重复的聊天来源，标题前用用户／GPT 图标区分消息；全局列表保留聊天名称。备注预览最多两行，第二行右端固定保留编辑图标，超出部分以 `...` 截断；打开编辑窗可查看完整备注，保存内容不被截短。
- 删除书签需在编辑窗再次确认，不影响聊天。并发修改或保存失败时保留草稿，不静默覆盖；冲突后请先复制草稿，再关闭编辑窗并重新打开合并。
- 备注独立保存在 `data/private/bookmarks.ceobe.json`，不改原消息，不写入派生 HTML、聊天 MD 或项目 ZIP。需要本地开发或生产服务读取和保存；纯静态页面不携带个人书签快照。
- 阅读区不提供 AI 续聊、听写或语音。保留的消息编辑、评价、分享、模型切换按钮仅说明本地未接入，不执行原操作；点赞不被改作书签。

### 搜索、置顶与项目

- 搜索覆盖本地聊天标题和正文，包括置顶和项目内聊天。标题命中列在“搜索结果”，正文命中列在下方的“正文命中”，每条显示所在聊天、命中片段及“用户／GPT · 第 N 轮”；点击即跳到该条消息并高亮（与书签定位相同）。正文索引在 `npm run library`（含导入后的重建）时生成，只包含阅读页可见的提问、最终回复和代码，不含推理过程、引用来源、附件内容和书签备注；正文命中最多显示 50 条，索引不可用时自动退回仅按标题搜索并在状态文字中说明。
- 聊天可置顶／取消置顶，或移至已有项目。按项目整理时，置顶聊天同时保留在顶部置顶区和所属项目中；项目内使用右侧置顶标记，取消置顶不会改变项目归属。
- 每条聊天的侧栏菜单和阅读顶部“更多”菜单都会在 MD 导出项旁边显示“打开本地文件夹”，在 Windows 资源管理器中打开这条聊天当前使用的本地归档快照目录（`archive/chatgpt-share/<聊天 ID>/<抓取时间>/`，内含 `conversation.md`、附件等）。此项需要本地开发或生产服务；只打开静态 HTML 或在非 Windows 系统上会提示无法打开。
- 顶部置顶聊天的项目名靠右显示并限制最大占宽，优先给聊天标题留空间；长项目名省略，悬停可查看全名。
- 从聊天的“移至项目 → 新项目”创建，会自动移入当前聊天；原侧栏“项目”行的“＋”只创建项目，不隐式移动聊天。
- 项目标题可直接点击重命名，也可以从侧栏项目菜单操作。
- 项目简介在设置内编辑，最多 4000 个字符。点击“保存简介”生效，关闭或 Esc 放弃未保存修改；冲突或失败时保留草稿，不直接覆盖其他窗口的更新。
- 新建项目时可以选择图标与颜色；已有项目可通过“项目设置”点击图标，复用同一选择器编辑，点击“完成”保存到本地。
- 支持预设颜色与 `#RRGGBB` 自定义颜色。Esc 或点击选择器遮罩取消未保存的选择；图标／颜色与项目简介分别保存。
- 保存后侧栏、项目详情、项目列表及移动菜单读取最新外观，刷新后保留。只读状态不允许修改；保存失败保留选择，并发冲突需关闭整个项目设置后重新打开，避免覆盖其他窗口。

侧栏收起、按列表／项目整理、分组展开等偏好保存在当前浏览器中，不更改聊天归档。

Windows 快捷键：`Ctrl+K` 搜索（标题和正文），`Ctrl+Shift+S` 开关侧栏，`Ctrl+Shift+O` 进入导入会话。

### 项目文件：自动汇总项目聊天附件

进入项目详情的“文件”标签，查看本项目聊天中的文件和图片。界面复用资料库的搜索、分类、排序、预览和下载方式，不需要手动添加或解除关联。

- 只统计当前项目的聊天。同一内容的文件去重显示，并保留它在当前项目中的来源聊天链接；项目外聊天不出现在这些链接或搜索范围里。
- 文件名称、别名和归档时间取自项目内的来源记录，来源聊天标题使用当前本地名称。
- 可按文件名或来源聊天标题搜索，使用“全部／图片／文件”分类，并按名称、归档时间、大小排序。
- 点击文件名打开预览，可下载原文件或返回来源聊天。未保存的附件仍显示记录和状态，不提供虚假预览或下载。
- 聊天移入／移出项目、导入或删除后重新统计；切回窗口或刷新也会更新。统计过程只读，不复制、移动或删除原文件。
- 项目没有附件时显示空状态，不用全局资料库内容填充。服务不可用时仅显示构建时的项目快照并明确提示，不能保证关联为最新。
- 旧“来源”的手动关联字段保留在本地，但不参与文件统计，旧添加／解除关联接口已停用。旧 `tab=sources` 地址兼容跳转到 `tab=files`。

项目文件不加入聊天 MD 或项目 ZIP，导出继续保持纯文本语义。

### 删除前请确认

- **删除项目**：只删除项目及关联，全部聊天、书签备注、附件和历史归档保留，聊天回到未归属状态。
- **删除聊天**：永久删除该聊天的全部归档版本、相关项目关联、该聊天的全部书签与备注及派生页面。其他聊天的独立附件副本保留。

永久删除不是隐藏条目；重要内容请先备份。

## 导出

### 单条聊天：Markdown

阅读顶部或聊天菜单的“另存为 MD”生成 `当前聊天标题.md`。

保留正文、代码、公式和表格等文本表达；图片、附件和普通链接转为可读文字，不复制资源文件。代码示例中的链接语法保持原样。

### 整个项目：ZIP

项目“另存为 ZIP”生成 `项目名称.zip`，内部每条聊天对应一个 `聊天标题.md`。

- 重复文件名自动编号，也处理大小写与 Unicode 兼容形式的冲突。
- 不包含附件、项目简介、项目文件、书签备注或完整消息树。
- 空项目可生成空 ZIP；存在缺失聊天时拒绝生成残缺包。
- 当前上限为 65,535 个文件、200 MiB 未压缩文本。

### 保存位置

受支持的 Edge／Chromium 安全上下文优先显示原生保存窗口。没有该接口时回退普通下载，保存位置由浏览器设置决定。取消原生保存不会开始读取导出内容；写入失败会提示，而不是报成功。

浏览器接口模拟与下载回退已经自动化测试；实际 Windows 保存窗口的目录选择、保存位置、取消与同名覆盖也已在使用者环境中验收通过。

## 数据与备份

| 路径 | 内容 | 是否需要备份 |
|---|---|---|
| `archive/` | 聊天原始响应、规范化 JSON、历史抓取、附件及报告；`archive/chatgpt-share/README.md` 是自动生成的“标题 ↔ 聊天 ID”索引，方便在磁盘上按标题找到 ID 命名的文件夹 | 是 |
| `data/private/` | 项目、简介、书签备注、聊天显示元数据、任务与恢复记录；也可能有私人开发捕获 | 是，按敏感数据保护 |
| `attachments/private/` | 若存在，本地私人附件 | 是 |
| `replay/`、`dist/` | 派生阅读页面与生产构建 | 可重建，不能替代源数据 |

建议等所有操作完成，停止本地服务后再复制备份，避免取得一半新、一半旧的状态。恢复到匹配的项目版本后，可用 `npm run library` 重新生成页面，再按需执行 `npm run build`。

浏览器里的折叠、排序等界面偏好不随这些目录一并迁移。MD／ZIP 导出也不是完整备份。

本地数据目录默认不纳入 Git，但截图、日志和手工复制的文件仍可能包含隐私，提交前应自行检查。

## 常见问题

### 导入或资源不完整

检查归档的 `import-report.json` 与资源状态。“结构检查通过”不代表所有附件都已下载。分享页面未提供的消息、受限附件及外部应用内容无法保证恢复；引用网站不会被递归保存。

### 只读提示、导入或导出不可用

确认正在使用本地开发或生产服务，而不只是打开静态 HTML。还应检查终端错误、网络连接、Python 和归档浏览器是否可用。

### 页面没有反映手动修改的归档

确保没有正在执行的写入操作，再运行 `npm run library`。生产模式随后运行 `npm run build`。不要使用演示命令代替档案库重建。

### 异常退出后提示工作区正在写入

`data/private/mutation.lock` 以及 `data/private/delete-jobs/*/journal.json` 可能记录未完成操作。先确认进程状态和恢复记录，**不要为了消除提示直接删除锁文件或恢复目录**。导入、项目与书签写入、聊天删除使用同一工作区锁。

## 命令行与演示

以下是高级入口，不是首次使用的必经步骤。执行会重建页面的命令前，请确认本地服务没有写入任务。

```powershell
# 直接归档分享链接，成功后更新档案库
npm run archive:share -- https://chatgpt.com/share/<share-id>

# 重建档案库，并选择默认首页
npm run library -- --select <share-id>

# 从单个 CEOBE JSON 生成阅读页面，不等同于完整档案库入口
npm run replay -- --input path/to/conversation.ceobe.json

# 显式启用测试样本演示；不会删除原始档案，但会替换派生页面
npm run replay:sample

# 从演示或单 JSON 回放回到真实档案库
npm run library
```

导入保存的分享 HTML 的底层工具：

```powershell
npm run import:share -- path/to/share.html --output path/to/conversation.ceobe.json
```

该工具生成 JSON；完整链接归档、资源下载和档案库更新请使用分享链接归档流程。详见[架构说明](architecture.md)。
